# Personal Dashboard

Личный командный центр: проекты, финансы, задачи и идеи в одном месте. Интерфейс из матового стекла
поверх вашей собственной фотографии. Работает в браузере на компьютере, iPad и телефоне.

**Сайт:** https://tsum323.github.io/dashbord/

Сервера, авторизации и аналитики нет. Все данные хранятся только в браузере устройства (IndexedDB).

## Что умеет

| Раздел | Возможности |
| --- | --- |
| Главная | Текущий бюджет, общий доход, расходы, чистая прибыль; активные проекты; быстрое добавление дохода, расхода, идеи, проекта; ближайшие задачи; последние операции и события; идеи на рассмотрении |
| Проекты | Каталог с поиском, фильтром по статусу, сортировкой, архивом. Страница проекта: описание, ссылки, статус, финансы проекта, задачи с главной следующей задачей, история событий, архивация, удаление |
| Доска проектов | Kanban: Идеи → В разработке → Тестирование → Запущено → Пауза → Завершено. Перетаскивание мышью и пальцем, смена статуса списком на карточке, поиск |
| Финансы | Журнал доходов и расходов в рублях: добавление, редактирование, удаление с подтверждением; фильтры по типу, периоду, проекту, категории; итоги по выборке |
| Лента событий | Хронология действий от новых к старым с фильтром по типам |
| Банк идей | Идеи с аудиторией, потенциалом, приоритетом, статусом и комментариями; поиск, фильтры, сортировка; «Превратить в проект» с предпросмотром и подтверждением |
| Настройки | Фоновое фото (загрузка, замена, поворот), затемнение, размытие, плотность стекла; начальный бюджет; экспорт и импорт JSON; версия |

При первом запуске мастер спрашивает начальный остаток и предлагает импортировать проекты,
подтверждённые после аудита GitHub. Там же можно восстановить данные из резервной копии.

## Запуск

Нужен Node.js 22+.

```bash
npm install
npm run dev        # http://localhost:5173/dashbord/
```

| Команда | Что делает |
| --- | --- |
| `npm run build` | проверка типов и сборка в `dist/` |
| `npm run preview` | просмотр собранной версии: http://localhost:4173/dashbord/ |
| `npm test` | автотесты расчётов, базы и резервных копий (vitest) |
| `npm run typecheck` | проверка типов TypeScript |
| `npm run e2e` | 18 сценариев ТЗ в браузере (нужны Playwright и запущенный `preview`) |

### Публикация

`.github/workflows/pages.yml` при каждом изменении `main` проверяет типы, запускает тесты,
собирает сайт и публикует его на GitHub Pages. Однократная настройка:
Settings → Pages → Build and deployment → Source: **GitHub Actions**.

### На телефоне и iPad

Откройте сайт в Safari → «Поделиться» → «На экран „Домой“». Приложение откроется без адресной строки,
а браузер не будет очищать его данные как у редко посещаемых сайтов.

## База данных

IndexedDB через Dexie, база `personal-dashboard`, версия схемы 1. Идентификаторы — UUID.
Деньги хранятся в **копейках** (целые числа), даты операций и сроки — `YYYY-MM-DD` в местном времени.

| Таблица | Поля | Связи |
| --- | --- | --- |
| `projects` | name, icon, description, status, archived, githubUrl, demoUrl, nextTaskId, sourceIdeaId, createdAt, updatedAt | nextTaskId → tasks, sourceIdeaId → ideas |
| `transactions` | title, type (income/expense), amount, date, category, projectId, comment | projectId → projects (необязательно) |
| `tasks` | title, description, projectId, priority, dueDate, status, completedAt | projectId → projects |
| `ideas` | title, description, audience, potential, priority, status, comments, projectId | projectId → проект, созданный из идеи |
| `events` | type, title, description, createdAt, projectId | projectId → projects (может указывать на удалённый проект — это история) |
| `settings` | ключ/значение: `setup` (начальный остаток), `appearance`, `background` (фото), `lastExportAt` | — |

**Расчёты** не хранятся отдельно, а вычисляются из операций:

- текущий бюджет = начальный остаток + все доходы − все расходы;
- чистая прибыль = доходы − расходы;
- проект: «Вложено» — расходы на разработку и оборудование, «Расходы» — подписки, AI-сервисы, реклама, прочее,
  результат = доход − вложено − расходы. Операции без проекта влияют только на общий бюджет.

**События ленты** пишутся в той же транзакции, что и изменение, ровно один раз на действие —
повторная отрисовка интерфейса их не создаёт.

**Удаление проекта:** его задачи удаляются, операции остаются в бюджете без привязки, события сохраняются.

## Резервное копирование

Настройки → «Экспорт JSON». На компьютере файл скачивается, на телефоне открывается «Поделиться»,
откуда его можно сохранить в «Файлы». Дата последнего экспорта видна там же.

Восстановление: Настройки → «Импорт JSON» (или «Восстановить из копии» в мастере первого запуска).
Приложение проверяет файл — принадлежность к Personal Dashboard, версию формата, типы полей, суммы, даты,
связи и уникальность ID — и показывает, что в нём. Данные заменяются только после подтверждения;
до него импорт можно отменить. Так же переносятся данные между устройствами.

Формат: `{ app: "personal-dashboard", formatVersion: 1, appVersion, exportedAt, data: { projects, transactions, ideas, tasks, events, settings } }`.
Файл из более новой версии формата не импортируется.

## Известные ограничения

- **Данные живут в одном браузере.** Синхронизации между устройствами нет — переносите их через экспорт/импорт.
  Очистка данных сайта в браузере удаляет всё; делайте экспорт регулярно.
- **Фоновое фото не входит в резервную копию** — его нужно выбрать заново на каждом устройстве.
  Текущее фото небольшого разрешения (1675×828), на больших экранах оно выглядит мягче.
- **Сведения о проектах из GitHub загружены один раз** при аудите (`src/data/confirmedProjects.ts`)
  и не обновляются автоматически: живой запрос к API не видит приватные репозитории без токена.
- **Репозиторий публичный:** код сайта и список подтверждённых проектов видны всем. Ваши данные — нет,
  они не покидают браузер.
- Порядок карточек внутри колонки Kanban не сохраняется — они сортируются по дате.
- Интерфейс проверен в Chromium с размерами экранов iPhone, iPad и компьютера; в реальном Safari
  стоит проверить безопасные зоны (вырез, «домашняя» полоска).
